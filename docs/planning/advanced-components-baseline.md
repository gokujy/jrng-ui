# JRNG UI Advanced Components — Baseline

Recorded on 2026-07-28 before advanced-component implementation.

## Repository state

- Branch: `jr`, tracking `origin/jr`.
- Workspace package: `jrng-ui-workspace` 0.1.0; published library package: `jrng-ui` 0.1.0.
- The library is an Angular standalone-component workspace with one secondary package entry point per public feature.
- The generated public registry contains **119 public components**. This is generated inventory, not proof that tests pass; executed validation is recorded below.
- Documentation is an Angular application. Component records live in `component-docs.data.ts`, generated registries/categories support discovery, generic and specialist preview components render examples, and scripts validate routes, completeness, examples, and displayed demo source.

- Packaging uses ng-packagr, `projects/jrng-ui/ng-package.json`, secondary-entry-point `ng-package.json` files, a prepared `dist/jrng-ui` package, and package/public-API verification scripts.

## Public architecture and conventions

- Public selectors use `j-`; public implementation classes use `.j-*`.
- Components are standalone and normally use signal inputs/outputs, `OnPush`, modern Angular control flow, and modular imports such as `jrng-ui/gantt`.
- Each secondary entry point has `public-api.ts`, `ng-package.json`, and package metadata; the root entry point intentionally stays small.
- The registry is generated by `scripts/generate-public-registry.mjs`; documentation inventory and registries are generated separately. Generated `tests` or status metadata must never be interpreted as an executed test result.
- Theme values come from semantic `--j-*` custom properties in the shared CSS/SCSS theme, with component-level token fallbacks.

## Relevant internal utilities

- Stable ID helpers and ARIA utilities in `jrng-ui/core`.
- Focus utilities, auto-focus, focus trapping, keyboard helpers, overlay keyboard/listener cleanup, and keyboard-shortcut services.
- `JLiveAnnouncerService` for polite screen-reader announcements.
- Browser-service abstractions, DOM guards, media-query service, accessibility preferences, clipboard/download/print services, and storage abstractions.
- Existing form controls and CVA conventions in Input, Select, Checkbox, Date Picker, Input Number, and related entry points.
- Shared semantic tokens, visible-focus utilities, disabled-state styling, reduced-motion rules, and logical-direction styling conventions.

Internal helpers for expression-tree operations, cron grammar, and barcode encoders do not yet exist and must remain private to their first consumer until reuse is demonstrated.

## Removed and forbidden components

- `j-data-grid` is absent from source and the public registry.
- It appears only in explicit removed-selector guard data in `scripts/component-categories.mjs` and `component-docs.data.spec.ts`.
- It must stay removed. Enterprise table features belong to `j-table`; hierarchical grid features belong to `j-tree-table`.

## Constraints for subsequent phases

- Implement Query Builder, Cron Expression Editor, and Barcode sequentially in isolated commits.
- Preserve standalone Angular architecture, SSR guards, explicit zoneless-compatible state updates, CVA conventions where applicable, RTL, responsive behavior, keyboard access, ARIA naming, visible focus, reduced motion, and disabled/read-only semantics.
- Reuse existing JRNG controls and core accessibility/browser services where doing so keeps entry points modular.
- Add no large mandatory runtime dependency. Keep the three new entry points tree-shakable.
- Run focused tests plus library/docs builds, lint, registry/API/package verification, SSR validation, and package dry run before handoff.
- Preserve public API compatibility, do not duplicate existing component responsibilities, do not reintroduce `j-data-grid`, and do not copy reference source, tests, CSS, structure, assets, or documentation.
